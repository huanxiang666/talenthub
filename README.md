# TalentHub 企业人才库

跨平台（Windows / Linux）企业人才库管理系统：**简历批量导入（PDF / Word / 图片，扫描版内置离线 OCR）→ 双引擎 AI 解析（本地小模型 / 外部联网大模型）→ 人工确认入库 → 精准管理 → 独立投递门户收简历 → 电子表格导出 / 导入 / 多库合并**，同一套仪表盘页面本机和局域网（开放端口）双通道可用，锁屏密码保护数据安全。

## 快速开始

**Windows**：双击 `run.bat`（首次自动装依赖，需已安装 Python 3.10–3.12 并勾选 Add to PATH）
**Linux / macOS**：

```bash
chmod +x run.sh && ./run.sh
```

启动后自动打开浏览器 `http://127.0.0.1:8300`（默认已开放端口 0.0.0.0，局域网设备可直接访问 `http://<本机IP>:8300`）。想换端口或改回仅本机：

```bash
./run.sh --port 9000 --host 127.0.0.1    # 命令行方式
# 或网页里「系统设置 → 访问范围/端口 → 保存并重启服务」
```

试用：进入「导入中心」，把 `samples/` 里的 4 个文件拖进去——`张伟-*.pdf` 走文字层直读、`李娜-*-扫描版.pdf` 走 OCR、`王强-*.docx` 走 Word 解析、`外部人才名单.xlsx` 在「表格导入」页签体验重复合并（张伟会按电话判定为重复）。

## AI 智能解析（双引擎，v1.2）

针对**非标准简历**（无字段标签、口语化描述、信息散落、乱排版）的三层方案：

1. **规则解析增强版**（始终可用，毫秒级）：22+ 字段、姓名黑名单防误抓、固话兜底、邮箱 `#`/`(at)` 变体归一、学位表述归一（工学学士→本科）、「至今」锚点定位当前公司、中文数字年限（"两年审计经验"）、日期推算年限、多段工作经历扫描、证书/语言词典。
2. **本地小模型引擎**（离线）：llama.cpp 推理 GGUF 模型（v1.5 起改用 **chat 模板调用 + few-shot 示例提示词**，instruct 模型 JSON 输出质量显著提升），规则置信度 < 阈值（默认 0.75，可调）的简历自动交给 AI 抽取 22 字段，再按**信任分层**与规则结果融合——
   - 语义字段（姓名/学校/专业/职位/城市…）AI 优先（修正规则的"非空但错误"值）
   - 数字/邮箱字段（电话/年龄/毕业年份）规则优先（小模型易幻觉改数字），规则空才由 AI 补
   - 时间字段（当前公司/工作经历）命中「至今」锚点时规则优先（小模型对时间先后判断不稳）
   - 技能/证书/语言两侧归一化合并去重
3. **外部 API 引擎**（联网，v1.2 新增）：设置页切换到「外部 API」，填任意 **OpenAI 兼容接口**（DeepSeek `https://api.deepseek.com/v1` + `deepseek-chat`、OpenAI、通义千问、Kimi、本地 Ollama `http://127.0.0.1:11434/v1`…）即接即用——解析质量高于本地小模型且不占本机资源。API Key 只存本机 `config.json`，设置页掩码显示不回显。

## 投递门户（第二端口，v1.2 新增）

启动后自动在**第二端口**（默认 8301，设置页可改/可关）开启独立的候选人投递页：

- **候选人**：打开投递页 → 填基本信息 + 期望职位 + **推荐人**（企业内推）+ 自我介绍 + 上传简历 → 过**图形验证码** → 提交成功得 **8 位查询码**。凭「手机号 + 查询码」在「查询/修改」页签随时查审核状态；**待审核期间可自助修改资料、替换简历文件**；被拒时能看到拒绝原因。
- **企业端**：主系统「投递审核」视图（侧栏角标提示待审核数）→ 窗口内**在线预览简历** → 「同意入选」自动解析其简历建档转入人才库（推荐人写入标签）或「拒绝」附原因。
- **防滥用**：一次性图形验证码（防重放）+ 同 IP 每小时 10 次 + 同手机号每日 3 次限频；文件类型/大小白名单、路径逃逸防护。完全可信内网可在设置页关闭验证码。
- 投递门户独立于锁屏：管理端上锁不影响候选人投递。

## 锁屏密码（v1.2 新增）

「系统设置 → 锁屏密码」设置 **6 位以上**自定义密码：

- 密码 PBKDF2-HMAC-SHA256 加盐（12 万次迭代）哈希后存 `data/lock.json`，明文不落盘。
- 启用后**所有数据 API 需解锁令牌**（HMAC 签名，12 小时有效）；页面加载即弹锁屏层，顶栏有「锁定」按钮，可配置 **N 分钟无操作自动锁定**。
- **防破解（v1.3）**：同一来源连续 5 次密码错误**冻结 60 秒**（锁屏页倒计时提示）；每次尝试（含冻结期）写入审计表，设置页可查看**失败警告记录与来源 IP**（保留最近 1000 条）。
- **忘记密码**：停止程序 → 删除 `data/lock.json` → 重新启动即清除锁屏（人才数据在 `data/talent.db`，完全不受影响）。锁屏页与设置页均内置该指引。

## 单文件二进制（免 Python 环境）

| 平台 | 产物 | 获取方式 |
|---|---|---|
| Linux | `dist/talenthub`（单文件 ~181MB，本仓库已构建） | 直接运行：`./dist/talenthub`，参数同 run.sh（`--port` / `--host 0.0.0.0` / `--no-open`） |
| Windows | `dist\TalentHub.exe` | PyInstaller 不支持 Linux→Windows 交叉编译，二选一：① 任意 Windows 机器双击 `build_windows.bat`（全自动，约 5-10 分钟）；② 推送到 GitHub 后用 `.github/workflows/build-binaries.yml` 云构建，Actions 页面直接下载 exe 工件 |

二进制特性（均已实测）：
- **零依赖**：Python 运行时、OCR 模型、ECharts、全部前端资源打进单文件；目标机器不需要装任何东西。
- **数据在 exe 旁边**：`data/`（SQLite 库+上传原件）和 `config.json` 生成于 exe 所在目录，整体拷贝即迁移。
- **热重启可用**：设置页「保存并重启服务」会重执行 exe 自身（已处理 PyInstaller onefile 的 `_PYI_*`/`LD_LIBRARY_PATH` 环境继承陷阱）。
- 首次启动需解压到系统临时目录，比源码模式慢 3-8 秒属正常。
- Linux 二进制在其它发行版运行需 glibc ≥ 构建机版本（本机 Ubuntu glibc 2.39 构建）；跨发行版分发建议用 GitHub Actions 或直接在目标机构建。

## 数据与安全说明

- 数据全部落在本地 `data/talent.db`（SQLite，WAL 模式）；删除 `data/` 即恢复出厂。锁屏密码独立存 `data/lock.json`（删除即解锁）。
- OCR 模型随 `rapidocr_onnxruntime` 包内置（约 90MB，首次 pip 安装时下载），之后**完全离线**运行。本地 AI 引擎同样全离线；仅「外部 API 引擎」为可选联网项，简历文本会发送给你配置的 API 服务商。
- 开放端口（0.0.0.0）后局域网内可访问管理页——**建议开启锁屏密码**保护数据；投递门户（第二端口）本就面向外部投递人，有验证码+限频防护。暴露公网请自行加防火墙白名单或反代鉴权。
- API Key（外部引擎）仅存本机 `config.json`，设置页掩码显示；Excel 导出防公式注入；上传全链路类型/大小白名单 + 路径逃逸防护。
- 备份建议：定期用「数据管理 → 导出 JSON 备份」，换机时「导入 JSON 备份并合并」。

## 已知限制（LIMIT）

| 限制 | 说明 / 升级路径 |
|---|---|
| 老式 `.doc` / `.xls` 二进制格式 | 纯 Python 无法解析，返回明确提示「另存为 .docx/.xlsx 后导入」；目标机装 LibreOffice 后可在 `app/extract/loader.py` 补 `soffice --convert-to` 自动转换 |
| 简历在线预览格式 | PDF / 图片窗口内直接预览；Word/TXT 看「解析原文」页签或下载原件（docx 转 PDF 预览需 LibreOffice，纯 Python 栈暂不做） |
| 本地小模型能力上限 | 1.5B 档对时间先后判断不稳（已由「至今」锚点保护）、偶有字段归类偏差（如把 Python 归入语言能力——已按词典过滤）；AI 明细里每次改动透明可查、草稿可人工修正；要更准用 8B/14B 档或外部 API 引擎 |
| 本地 LLM 单份 25-30s（纯 CPU） | 批量导入默认只对低置信度简历启用 AI；GPU 卸载或外部 API 引擎可大幅提速 |
| 锁屏为单密码模型 | 无多用户/角色权限（定位是内网/单机工具）；锁屏令牌 12h 有效，浏览器 sessionStorage 存储，关标签页即需重新解锁 |
| 投递限频计数在内存 | 重启服务后 IP/手机号限频计数清零；单机场景足够，多实例部署需换共享存储 |
| OCR 单文档页数上限 | 默认 30 页（设置页可调），防超大扫描件阻塞 |
| e2e 测试需空库 | `scripts/e2e_test.py` 断言基于从零导入的计数，重跑前删除 `data/`（保留 `data/models/`） |
