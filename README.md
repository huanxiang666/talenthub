# TalentHub 企业人才库

跨平台（Windows / Linux）企业人才库管理系统：**简历自动提取（PDF / Word / 图片，扫描版内置离线 OCR）→ 结构化解析 → 人工确认入库 → 精准管理潜在人才 → 电子表格导出 / 导入 / 多库合并**，同一套仪表盘页面本机和局域网（开放端口）双通道可用。

```
┌─────────────── 浏览器（本机自动弹出 / 局域网访问同一地址）───────────────┐
│  仪表盘(ECharts) │ 人才库(搜索/筛选/批量/详情抽屉) │ 导入中心 │ 数据管理 │ 设置 │
└──────────────────────────────┬──────────────────────────────────────┘
                        FastAPI (REST + 静态页面)
        ┌───────────────┼────────────────┬─────────────────┐
   提取管线          解析引擎          人才服务          表格服务
 pdfplumber/docx   规则+词典解析    CRUD/统计/合并    openpyxl 导入导出
 pypdfium2 渲染    置信度评分       去重(电话>邮箱>姓名)  别名表头自动映射
 RapidOCR(离线)                     SQLite (WAL)
```

## 功能清单

| 模块 | 能力 |
|---|---|
| 简历自动提取 | PDF 文字层直读；**扫描版 PDF / 图片自动走内置 OCR**（RapidOCR，PP-OCRv4 模型，中英混排，完全离线）；Word .docx（段落+表格按文档顺序，纯图片 docx 也能 OCR）；txt/md |
| 结构化解析 | 姓名、电话、邮箱、性别、年龄、城市、学历、毕业院校、专业、工作年限、当前公司/职位、期望职位/薪资、技能（120+ 词典）、自我评价；每份给 **解析置信度**，低于 60% 前端标黄提示人工核对 |
| 精准管理 | 状态流水线（潜在→跟进中→已邀约→已面试→已录用/不合适/已归档）、A/B/C/D 潜力评级、标签、跟进记录时间线、全文搜索、多条件筛选、批量改状态/评级/打标签/删除、原件回看下载 |
| 电子表格 | **导出** 带格式 xlsx（人才列表+数据概览双 sheet、冻结首行、自动筛选、状态/评级着色）与 csv（utf-8-sig，Excel 双击不乱码）；**导入** xlsx/csv，表头别名自动映射（手机号码/联系方式/最高学历…都认）；**导入模板** 自带示例行和填写说明 |
| 数据合并 | 四种策略：跳过重复 / 补全空字段 / 覆盖更新 / 总是新增；去重键优先级 **电话 > 邮箱 > 姓名**；导入前预览页给出「新记录 N / 疑似重复 M（按什么匹配）」逐行分析；JSON 全量备份导出 + 跨机器合并导入（幂等，skip 策略重复导入 0 新增） |
| 双页面 + 开放端口 | 本机运行自动弹浏览器（可关）；设置页一键切「仅本机 127.0.0.1 / 开放端口 0.0.0.0」+ 改端口，**保存并重启服务**热生效；局域网设备访问同一地址即用同一套仪表；设置页展示本机 + 局域网访问地址 |
| 仪表盘 | 4 统计卡（总数/本月新增/高潜 A+B/跟进中）+ 5 图（近 12 月新增趋势、学历分布环图、状态横条、技能 TOP10、来源渠道玫瑰图），图旁结论句由数据实时算出，每图可存为 PNG |

## 快速开始

**Windows**：双击 `run.bat`（首次自动装依赖，需已安装 Python 3.10–3.12 并勾选 Add to PATH）
**Linux / macOS**：

```bash
chmod +x run.sh && ./run.sh
```

启动后自动打开浏览器 `http://127.0.0.1:8300`。想换端口或开放给局域网：

```bash
./run.sh --port 9000 --host 0.0.0.0      # 命令行方式
# 或网页里「系统设置 → 访问范围/端口 → 保存并重启服务」
```

试用：进入「导入中心」，把 `samples/` 里的 4 个文件拖进去——`张伟-*.pdf` 走文字层直读、`李娜-*-扫描版.pdf` 走 OCR、`王强-*.docx` 走 Word 解析、`外部人才名单.xlsx` 在「表格导入」页签体验重复合并（张伟会按电话判定为重复）。

## 单文件二进制（免 Python 环境）

| 平台 | 产物 | 获取方式 |
|---|---|---|
| Linux | `dist/talenthub`（单文件 ~181MB，本仓库已构建） | 直接运行：`./dist/talenthub`，参数同 run.sh（`--port` / `--host 0.0.0.0` / `--no-open`） |
| Windows | `dist\TalentHub.exe` | PyInstaller 不支持 Linux→Windows 交叉编译，二选一：① 任意 Windows 机器双击 `build_windows.bat`（全自动，约 5-10 分钟）；② 推送到 GitHub 后用 `.github/workflows/build-binaries.yml` 云构建，Actions 页面直接下载 exe 工件 |

二进制特性（均已实测）：
- **零依赖**：Python 运行时、OCR 模型、ECharts、全部前端资源打进单文件；目标机器不需要装任何东西。
- **数据在 exe 旁边**：`data/`（SQLite 库+上传原件）和 `config.json` 生成于 exe 所在目录，整体拷贝即迁移。
- **热重启可用**：设置页「保存并重启服务」会重执行 exe 自身（已处理 PyInstaller onefile 的 `_PYI_*`/`LD_LIBRARY_PATH` 环境继承陷阱）。
- 首次启动需解压到系统临时目录，比源码模式慢 3-8 秒属正常。
- Linux 二进制在其它发行版运行需 glibc ≥ 构建机版本（本机 Ubuntu glibc 2.39 构建）；跨发行版分发建议用 GitHub Actions 或直接在目标机构建。

## 数据与安全说明

- 数据全部落在本地 `data/talent.db`（SQLite，WAL 模式），无任何外部服务依赖；删除 `data/` 即恢复出厂。
- OCR 模型随 `rapidocr_onnxruntime` 包内置（约 90MB，首次 pip 安装时下载），之后**完全离线**运行。
- 默认只监听 127.0.0.1；开放端口（0.0.0.0）后局域网内任何人可访问且**本系统无登录鉴权**——仅建议在可信内网使用；要暴露公网请自行加防火墙白名单或反代鉴权（如 nginx basic auth）。
- 备份建议：定期用「数据管理 → 导出 JSON 备份」，换机时「导入 JSON 备份并合并」。

## 已知限制（LIMIT）

| 限制 | 说明 / 升级路径 |
|---|---|
| 老式 `.doc` / `.xls` 二进制格式 | 纯 Python 无法解析，会返回明确提示「另存为 .docx/.xlsx 后导入」；目标机装 LibreOffice 后可在 `app/extract/loader.py` 补 `soffice --convert-to` 自动转换 |
| 解析引擎为规则+词典 | 零依赖、可离线、可解释；姓名/电话/邮箱等关键字段实测准确，非标版式靠置信度标黄+人工确认兜底。要更高精度可换 NLP 模型，接口在 `app/extract/parser.py:parse_resume` |
| 无登录鉴权 | 定位是内网/本机工具；多用户与权限需另加认证层 |
| OCR 单文档页数上限 | 默认 30 页（设置页可调），防超大扫描件阻塞 |
| 「保存并重启服务」立即生效 | 重启不等待进行中的请求；大文件 OCR 解析中途重启会中断该次解析（数据库有 WAL 保护不受影响），重新上传即可 |
| e2e 测试需空库 | `scripts/e2e_test.py` 的断言基于从零导入的计数，重跑前删除 `data/` 或换空库实例 |
